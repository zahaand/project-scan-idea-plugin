# Implementation Plan: Baseline — Static Curated Code-Quality Rules Module

**Branch**: `003-baseline-rules-module` | **Date**: 2026-06-14 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/003-baseline-rules-module/spec.md`

## Summary

Implement the `:baseline` Gradle submodule: a self-contained, pure-Kotlin module that bundles
a curated `rules.json` resource (≥13 rules across 9 categories), parses and validates it on
first access via `kotlinx-serialization`, caches the immutable result, and exposes the
complete unfiltered `List<BaselineRule>` through a single `BaselineRuleProvider` object. All
baseline-specific types (`BaselineRule`, `BaselineLevel`, `BaselineCategory`, `Obligation`,
`BaselineLanguage`, `BaselineLoadException`) are defined within `:baseline`. The module has
zero dependency on `:scan`, zero IntelliJ Platform types, and is exercised entirely by pure
JUnit 5 tests.

## Technical Context

**Language/Version**: Kotlin 2.2.20, JDK 21 (JetBrains Runtime)
**Primary Dependencies**: `kotlinx-serialization-json 1.7.3` (parsing); `:model` (permitted but
not consumed in Sprint 3 — present as an architectural anchor per spec input)
**Storage**: In-process lazy cache only — `rules.json` is a bundled classloader resource; no
filesystem writes
**Testing**: JUnit 5 (pure JVM; no IntelliJ Platform fixtures)
**Target Platform**: JVM only; no IntelliJ API surface in this module
**Project Type**: Gradle submodule within an IntelliJ Platform Plugin (module itself is
platform-agnostic)
**Performance Goals**: No explicit latency target; `rules.json` is loaded once per JVM lifetime
**Constraints**: Zero dependency on `:scan` (FR-013); baseline data types in `:baseline` not
`:model` (FR-015); `kotlinx.serialization` is the only permitted JSON library (FR-003)
**Scale/Scope**: Fixed-size curated rule set (≥13 rules); no runtime growth or dynamic loading

category coverage (US4).
